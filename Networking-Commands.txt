NETWORKING COMMANDS — LINUX / DEVOPS / CLOUD PRACTICAL REFERENCE
================================================================
Hinglish inline explanations | Ubuntu/Debian and RHEL families
Examples Linux shell ke liye hain. eth0, ens33, IP, domain aur gateway apne environment ke hisab se replace karo.
Ye reference hai, executable script nahi. Saare commands ek saath mat chalana.
CHANGE = configuration badlegi; DANGER = connectivity/data loss possible. Remote SSH par especially careful raho.
Packet capture aur scanning sirf authorized systems par karo. Captures mein sensitive data ho sakta hai.

21. PRODUCTION TROUBLESHOOTING ORDER
-------------------------------------
# 1. ip -br a aur ip -s link: Link, IP aur packet errors check karo.
# 2. ip route get DESTINATION: Selected path aur source IP check karo.
# 3. getent hosts DOMAIN aur dig DOMAIN: DNS issue isolate karo.
# 4. ping aur traceroute: ICMP aur path test karo; ICMP block hone se app down prove nahi hoti.
# 5. nc -vz HOST PORT: TCP connectivity verify karo.
# 6. ss -ltnp: Server par listener aur process verify karo.
# 7. curl -v URL: TLS, HTTP aur application response check karo.
# 8. Firewall, security groups, NACL, routes aur return path inspect karo.
# 9. tcpdump: Authorized capture se SYN, SYN-ACK, RST aur retransmission inspect karo.
# 10. sar, ss -ti, ethtool -S: Latency, congestion, drops aur NIC errors check karo.
# 11. Kubernetes mein Service selector, EndpointSlice, readiness, DNS aur NetworkPolicy check karo.
# 12. 502 upstream response issue, 503 unavailable backend, 504 upstream timeout ho sakta hai; logs se actual cause verify karo.
# 13. Cloud firewall/NACL/security group changes host firewall se alag hote hain.
# 14. Changes se pehle backup, rollback plan aur console access ready rakho.
