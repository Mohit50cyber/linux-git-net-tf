PART 1: AWS / SYSTEM DESIGN - 80 SCENARIO BASED QUESTIONS
=====================================================================

HOW TO ANSWER (har question ke liye):
1. Pehle requirement aur constraint clearly likho (scale, cost, latency, availability, compliance).
2. Jo service choose kar rahe ho, kyun kar rahe ho - detail mein prose mein.
3. Alternatives kyun reject kiye (jaise ECS ki jagah EKS kyun nahi).
4. Cost ka trade-off, operational overhead, aur failure scenarios.
5. Scale 10x ya 100x ho jaye to kya change hoga.
Sirf diagram mat banao. Har component ka role aur data flow words mein explain karo.

SCENARIO BASED QUESTIONS (SENIOR CLOUD ENGINEER)

HOW TO ANSWER:
1. Pehle problem ko narrow down karo: kya check karoge, kis order mein, aur kyun.
2. Commands ke naam bolo (ss, dig, kubectl describe, terraform state, etc.) aur batao ki output se kya pata chalta hai.
3. Root cause aur permanent fix alag-alag explain karo (quick fix vs long-term fix).
4. Production mein kya risk hai, wo bhi batao.

SECTION A: LINUX (15 Questions)
---------------------------------------------------------------------

Q1. Production server slow hai. Tum SSH karte ho. Step-by-step kya check karoge? (load average, CPU, memory, disk I/O, network) Har step pe kaunsa command use karoge aur output se kya samjhoge?

Q2. Server pe disk 100% full dikha raha hai, lekin "du" se jodne par space kam nikalta hai. Aisa kyun ho sakta hai? (deleted files jo process ne khole rakhe hain, inode exhaustion) Kaise debug aur fix karoge?

Q3. Load average 20 hai lekin CPU usage sirf 10% hai. Iska matlab kya ho sakta hai? (I/O wait, uninterruptible sleep, D state processes) Kaise investigate karoge?

Q4. Ek process ko Linux ne OOM killer se maar diya. Kaise confirm karoge? Kya root cause ho sakte hain? Memory limits, swap, aur overcommit ka role samjhao.

Q5. Zombie process aur orphan process mein kya difference hai? Zombie kaise bante hain aur unhe kaise saaf karoge?

Q6. "Too many open files" error aa raha hai. ulimit, file descriptors aur systemd limits ka relation samjhao. Permanent fix kaise karoge?

Q7. Ek service reboot ke baad automatically start honi chahiye aur fail ho to restart bhi. systemd unit file kaise likhoge? journalctl se logs kaise dekhoge?

Q8. File permissions, setuid, sticky bit aur ACLs kya hain? Ek shared directory mein multiple users ko kaam karna hai lekin ek doosre ki files delete nahi kar sakte, kaise set karoge?

Q9. EC2 instance pe CPU slow lag raha hai lekin application load normal hai. CPU steal time, T-series CPU credit exhaustion aur noisy neighbor ko kaise detect karoge (top, mpstat, CloudWatch)? Permanent fix kya hoga?

Q10. Ek process hang ho gaya hai: na CPU kha raha hai na response de raha hai. strace, lsof, perf, pstack aur /proc se kaise investigate karoge? eBPF tools (bcc, bpftrace) kab useful hain?

Q11. EBS volume pe disk latency high hai. iostat -x, await, util% aur queue depth se kya samjhoge? gp3 IOPS/throughput limits, burst balance, aur instance-level EBS bandwidth limit ka role batao.

Q12. Memory ke bare mein: "free" kam dikha raha hai lekin kya sach mein problem hai? Page cache vs available memory, swap thrashing, slab leak, aur memory leak ko vmstat, smem aur /proc/meminfo se kaise pakdoge?

Q13. EC2 instance reboot ke baad SSH nahi ho raha (galat fstab ya sshd config). Bina SSH ke recover kaise karoge? SSM Session Manager, EC2 Serial Console, aur volume detach/attach ka flow batao.

Q14. 1,000 Linux servers ko zero-downtime patch kaise karoge? SSM Patch Manager vs immutable golden AMI pipeline, canary patching, kernel live patching, aur rollback ka plan batao.

Q15. Compliance (CIS/PCI) ke liye Linux hardening plan: SSH config, sudo policies, auditd, SELinux/AppArmor, FIPS mode, file integrity monitoring, aur continuous compliance verification (Inspector, Config).

Q49. Container mein app root user se chal raha hai. Ye risk kyun hai? Non-root user, read-only filesystem, capabilities drop, aur image scanning (Trivy, ECR scanning) ka plan batao.

Q50. Container start hote hi exit ho jaata hai. Kaise debug karoge? (docker logs, docker inspect, exit codes 0/1/137/139, docker run -it debug) Exit code 137 ka matlab kya hota hai?

Q51. Data persistence: volumes vs bind mounts vs tmpfs. Container delete hone par data kyun jaata hai? Production mein stateful workloads container mein chalana chahiye ya nahi?

Q52. Docker networking modes (bridge, host, none, overlay) explain karo. Do containers ek doosre se naam se kaise baat karte hain? Port mapping ke peeche kya hota hai?

Q53. Container runtime internals: Docker Engine, containerd, runc, aur OCI spec ka relation. Kubernetes ne Docker (dockershim) kyun hataya aur ab kaunsa runtime use hota hai?

Q54. Image supply chain security design karo: trusted base images, automated patching pipeline, image signing (cosign), SBOM, ECR immutable tags, vulnerability scanning gates, aur admission-time verification.

Q55. Image tagging strategy: "latest" tag production mein kyun bura hai? Semantic version vs git SHA vs digest pinning. Rollback aur reproducibility kaise ensure karoge?

Q56. Container CPU/memory limits aur runtime ka relation: JVM ya Node.js cgroup limits ko respect karte hain ya nahi? docker stats, cgroup files, aur galat heap sizing se OOMKill kaise hota hai?

Q57. PID 1 problem: container mein SIGTERM app tak kyun nahi pahunchta aur zombies kyun jama hote hain? tini/dumb-init, exec form vs shell form (CMD), aur graceful shutdown kaise ensure karoge?

Q58. CI mein Docker builds slow hain (15 minute). BuildKit cache mounts, remote/registry cache, layer ordering, multi-arch builds (amd64 + arm64 Graviton) aur build ko parallelize kaise karoge?

Q59. Docker build mein secrets (npm token, SSH key) kaise handle karoge? Build args aur ENV layers mein kyun leak hote hain (docker history)? BuildKit secret mounts aur multi-stage ka role batao.

Q60. Container escape aur privileged containers ka risk: docker.sock mount karna kyun khatarnak hai? seccomp, AppArmor, user namespaces, rootless containers, aur gVisor/Firecracker jaise stronger isolation kab chahiye?

SECTION E: KUBERNETES (15 Questions)
---------------------------------------------------------------------

Q61. Kubernetes architecture explain karo: control plane (API server, etcd, scheduler, controller manager) aur worker node (kubelet, kube-proxy, container runtime). "kubectl apply" karne se pod chalne tak poora flow batao.

Q62. Pod CrashLoopBackOff mein hai. Debug flow batao: kubectl describe, logs, logs --previous, events, liveness probe fail, config/secret missing, resource limits. Har kaaran ka alag fix kya hoga?

Q63. Pod "Pending" state mein atka hai. Kaaran kya ho sakte hain? (insufficient resources, node selector/affinity, taints, PVC unbound, quota) Kaise diagnose karoge?

Q64. Pod OOMKilled ho raha hai. Requests aur limits ka difference samjhao. CPU throttling aur memory kill mein kya fark hai? QoS classes (Guaranteed, Burstable, BestEffort) ka role batao.

Q65. Liveness, readiness aur startup probes ka difference batao. Galat probe configuration se outage kaise ho sakta hai? Ek slow-starting app ke liye kya setup karoge?

Q66. Kubernetes Services: ClusterIP, NodePort, LoadBalancer aur Ingress ka difference. Internal communication aur external traffic ke liye kaunsa kab use karoge? Service ke peeche traffic kaise route hota hai (kube-proxy, iptables/IPVS, endpoints)?

Q67. HPA, VPA aur Cluster Autoscaler (ya Karpenter) kaise kaam karte hain? Pod scale-out hua lekin node nahi mila to kya hoga? Metrics server aur custom metrics ka role kya hai?

Q68. RBAC kaise kaam karta hai? Role, ClusterRole, RoleBinding, ServiceAccount. Ek developer ko sirf ek namespace mein pods dekhne ka access dena hai, kaise setup karoge? EKS mein IAM ke saath mapping (IRSA / Pod Identity) kaise hota hai?

Q69. Kubernetes mein zero-downtime deployment kaise karoge? Rolling update strategy (maxSurge, maxUnavailable), PodDisruptionBudget, graceful shutdown (preStop, terminationGracePeriod), aur readiness probe ka relation samjhao.

Q70. Stateful workloads: Deployment vs StatefulSet. PersistentVolume, PVC, StorageClass kaise kaam karte hain? Node fail hone par pod doosri AZ mein jaye to EBS volume ka kya hoga?

Q71. Secrets aur config management: ConfigMap vs Secret. Secrets base64 hote hain, encrypted nahi, to kaise secure karoge? (encryption at rest, External Secrets Operator, Secrets Manager, Sealed Secrets)

Q72. Kubernetes cluster ko secure kaise karoge? Network policies, Pod Security Standards, image policies (admission controllers), private API endpoint, node hardening, aur runtime security (Falco) ka plan batao.

Q73. EKS cluster upgrade kaise karoge production mein bina downtime ke? Control plane vs node group upgrade, deprecated APIs, add-on compatibility, aur rollback plan kya hoga?

Q74. Cost optimization on Kubernetes: over-provisioned requests, idle nodes, Spot nodes, bin packing, Karpenter consolidation, aur namespace-level cost visibility (Kubecost) kaise implement karoge?

Q75. Incident scenario: cluster upgrade ke baad achanak pods evict ho rahe hain, ImagePullBackOff aa raha hai aur API server overloaded hai. Triage flow, communication, rollback/mitigation aur post-incident (blameless postmortem) kaise handle karoge?

BONUS TIPS (interview / Amex fintech)
=====================================================================
- Hamesha pehle clarifying questions poochho: users kitne, read/write ratio, latency target, budget, compliance.
- Har choice ka "kyun" aur "kyun nahi" dono batao. Yahi senior level ki pehchaan hai.
- Cost, reliability, security, performance, operational simplicity: ye 5 axes pe har design ko tolo (Well-Architected Framework).
- Pehle simple design (1 server, 1 DB) se shuru karo, phir bottleneck dhundh ke step-by-step scale karo.
- Troubleshooting questions mein hamesha "pehle kya check karoge aur kyun" bolo, seedha guess mat karo.
- Har fix ke baad "future mein ye dobara na ho, iske liye kya karoge" zaroor batao (alerting, automation, runbook).
- Real production story sunao (STAR format: Situation, Task, Action, Result). Senior interviews mein ye bahut kaam aata hai.
- Fintech mein compliance (PCI-DSS, SOX, audit trails, data residency) aur correctness (idempotency, no double charge) ko har design mein mention karo.
- Numbers batao: QPS, latency budget, RPO/RTO, downtime per year (99.99% = ~52 min/year).
- Failure mode thinking: har component ke liye "ye fail hua to kya hoga" aur blast radius clearly bolo.
